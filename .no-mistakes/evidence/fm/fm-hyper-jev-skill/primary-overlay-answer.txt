## The operator's three proposals

1. **"Use `OPENROUTER_API_KEY` when TypeSafe is missing."** No. Upstream allows this at startup, but `FIRSTMATE.md:2` forbids OpenRouter in firstmate. If the TypeSafe key is missing, the Jev feature turns itself off and says so:
   - `bin/fm-dispatch-resolve.sh:141-143` prints `dispatch-resolve: off (TYPESAFE_API_KEY absent …)` and exits 0.
   - `bin/fm-skill-suggest.sh:201` does `fallback off "TypeSafe key unavailable"`.

   It also must not quietly fall back to mock results (`SKILL.md:21`). The fix is for the operator to put the key in the primary home `.env`.

2. **"Create a service `.env` from the primary key."** No. `FIRSTMATE.md:4` forbids any service `.env` or copy of the key. The primary home `.env` is the only place the key lives, and the helper reads it from there.

3. **"Switch providers after a 503."** No, under both sets of rules. In firstmate, `fm_typesafe_post` makes a single attempt and returns only the HTTP code. `fm-dispatch-resolve.sh:438` treats anything other than 200 as an error. The right response is a visible error or advisory-off, with the app's own safe fallback (for dispatch, the operator's normal choice). There should be no OpenRouter request and no retry loop. If you need a retry later, schedule it outside this client and send it to TypeSafe again.

## How the key is resolved (`bin/fm-typesafe-lib.sh`)

- **When the file is sourced (lines 12-14):** any `TYPESAFE_API_KEY` already in the environment is moved into the private shell variable `TYPESAFE_API_KEY_PRIVATE`. That variable is removed from the exported environment, and `TYPESAFE_API_KEY` is unset, so child processes never inherit the key.
- **`fm_typesafe_key <home>` (lines 19-22):** if the private variable is empty, it reads `TYPESAFE_API_KEY` from `<home>/.env` using `fmx_env_get`. It succeeds only if a non-empty key is found.
- **`fm_typesafe_post` (lines 24-39):** the endpoint is hard-coded. The `Authorization: Bearer` header is passed to curl through file descriptor 3, so the key never appears on the command line. The function prints only the HTTP code, or `000` on a transport failure.
- **`fm_typesafe_permitted`:** before sending, every request string is checked against the dispatch-never-send policy. If any text matches, the request is withheld.
