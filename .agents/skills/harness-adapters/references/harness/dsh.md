# dsh (DeepSeek Harness)

dsh is the terminal frontend for DeepSeek Harness, launched through `dsh-tui`.
It supports workers and scouts, and primary or secondmate sessions through the tracked native plugin loaded by `../../../bin/fm-dsh-primary.sh` or the secondmate launch patch.
Primary and secondmate supervision requires Perl for the shared owner-bound watcher watchdog; it has no lifetime deadline and terminates only its owned subtree on native process death or disposal.
A bare `dsh-tui` is detectable but does not load Firstmate's primary supervision adapter automatically; [the DSH protocol](../../../docs/supervision-protocols/dsh.md) owns that boundary and recovery.
`bin/fm-dsh-primary.sh --resume` reuses the binding's model and effort unless they are given, and refuses rather than replace a recorded conversation it cannot resume; neither form starts while a live DSH session holds the home's session lock.
With no `--model` and no resumed binding, `bin/fm-dsh-primary.sh` reads the operator's dsh-tui `/model` choice from `.dsh-tui/model.json` in the operator home (`FM_DSH_OPERATOR_HOME`, else `HOME`) at launch through `bin/fm-dsh.py preferred-model`, and refuses naming `--model` when that file names no `deepseek-official` model; the launcher carries no built-in model id.
A dsh crew or secondmate harness resolved without a model, including one mirrored from a DSH primary, carries that session's bound model read at spawn time by `bin/fm-dsh.py own-model`, and refuses naming the missing model configuration when no live record supplies one.
A relaunch of a task already running dsh never silently discards its conversation, through `bin/fm-control.sh` and a direct `bin/fm-spawn.sh --relaunch` alike: with no `--model`, or with `--model` naming the recorded model or a role that resolves to it and no `--effort`, it keeps the recorded model and effort and resumes the bound conversation; a plain `bin/fm-control.sh` relaunch whose config/secondmate-harness names a different model or effort, compared after role resolution, refuses before the stop, and an explicit `--model` or `--effort` that differs from the recorded profile starts a fresh conversation.
Spawns from inside a DSH primary or secondmate stage packages and credentials from `FM_DSH_SOURCE_HOME`, the operator's DSH install captured before the private swap, never from that session's own runtime copy.
Runtime evidence is owned by [runtime verification](../../../docs/verification/runtime-backends.md#deepseek-harness-dsh-tui); portable regressions are [`tests/fm-dsh-harness.test.sh`](../../../tests/fm-dsh-harness.test.sh) for the adapter helper and [`tests/fm-dsh-spawn.test.sh`](../../../tests/fm-dsh-spawn.test.sh) for detection, the spawn route and launch environment, launch policy, and busy and liveness classification, and the live lifecycle guard is [`tests/fm-dsh-live-e2e.test.sh`](../../../tests/fm-dsh-live-e2e.test.sh).

## Operating facts

| Fact | Value |
|---|---|
| Binary | `../../../bin/fm-dsh-lib.sh` resolves `dsh-tui` and `dsh` from `PATH` and requires their version commands to succeed without comparing release numbers. The launch carries the exact probed `PATH` into the pane, so the CLI and Node being probed are the ones the launcher finds even when an older pane shell has a different search path. A missing executable or failed command refuses before an endpoint exists; the actual launch must also prove a recognized composer through `bin/fm-composer-lib.sh` and a new durable turn. |
| Launch | `../../../bin/fm-spawn.sh` owns the exact template: a per-launch `HOME` and `DSH_HOME`, `--patch <launch.yml>`, then `-- <brief>` as the opening prompt, for workers, scouts and secondmates alike; a secondmate's native plugin adds its session-start digest ahead of that brief inside the first step. The spawn succeeds only once the session log records a turn that started beyond the log position `bin/fm-dsh.py position` took before launch, so a resumed relaunch cannot pass on the earlier conversation. No operator profile or credential file is mutated. |
| Model and effort | `dsh-tui` exposes no model or effort launch flags, so `bin/fm-dsh.py prepare` writes the exact route into the launch-local patch and the launch-local `~/.dsh-tui/model.json` and `effort.json`. Effort accepts the `low`, `medium`, `high`, `xhigh`, and `max` levels. |
| Busy state | `../../../bin/fm-busy-lib.sh` source `dsh-session-log`: `bin/fm-dsh.py state` folds the launch's own plain JSONL session log, the highest-numbered `session.v*.jsonl` whatever its number, and reports busy on the last durable `turn/start` and idle on `turn/end`. The log is admitted by behavior, not by schema number: it must open with a `session` header and hold events with a `type` and a strictly increasing integer `seq`. A missing log, or one that fails a check, reads `unknown: <the failed check>`, and a spawn that never proves a turn reports that check. The fold starts at the newest `turn/start`, found by a bounded backward scan, so a turn larger than one chunk of the log still reads busy. The launch configures `session-persistence-jsonl` with `compression: none` and a launch-local `root`, so no plugin is required. |
| Exit command | `/exit` (`/quit` and `/q` are aliases). |
| Interrupt | Escape; the interrupt key table in `../../../bin/fm-control-lib.sh` carries it. |
| Resume | `bin/fm-dsh.py resume` rewrites the task's launch patch with its newest session id in the `dsh-tui` row's `sessionId` field, and DSH continues that conversation in place, appending to the same session log. The overlay is what makes this work: the launch patch replaces the stock profile patch field that reads `DSH_TUI_RESUME_SESSION`, so the env or `--resume` flag alone silently opened a fresh session. Verified by a live probe in which a resumed session recalled a secret word from the earlier turn, and by the live lifecycle guard's same-log growth and earlier-conversation assertions. The durable fold follows the newest depth-zero log. A resume that cannot be proven (a changed model, effort, or working directory, or a missing binding or log) prepares a fresh launch from the new instructions; the primary launcher refuses instead. |
| Marker | `FM_DSH_HARNESS=dsh` is Firstmate's launch marker; DSH publishes none of its own. Ancestry matches the anchored process names `dsh` and `dsh-tui`, plus a Node argv whose script is the `dsh-tui` launcher (for example `node /opt/homebrew/bin/dsh-tui`) or any script inside a `@deepseek-harness-tui/dsh-tui` package directory, installed or staged in the launch root. No internal package file path is part of that identity. |
| Trust | No folder-trust or permission dialog was observed on a fresh local copy or a fresh git repository running a shell command under the default workspace-write policy. The onboarding guide is dismissed with Escape, and `DSH_TUI_NO_LAUNCHPAD=1` bypasses the launchpad. |
| Composer | A rounded frame whose side rows open with `⌸` and close with `⛶`, holding the `❯` prompt glyph; `../../../bin/fm-composer-lib.sh` proves it as a bordered box, and the rendered busy footer is `esc to interrupt`. |
| Autonomy | `DSH_PERMISSION_MODE=danger-full-access` at the launch boundary selects DSH's own `danger-full-access` sandbox and `never` approval policy. The default `workspace-write` posture is unusable for a worker: a firstmate worker writes its steering inbox and status record outside the workspace, and that write parked a live worker on an `Awaiting approval` panel until the environment was changed. |

## Detection

`../../../bin/fm-harness.sh` accepts `FM_DSH_HARNESS=dsh` only when the ancestry walk reaches a real dsh process or launcher argv, so an inherited marker is inert.
The dsh template clears every foreign marker at its own boundary, and the omp template clears `FM_DSH_HARNESS` for the same reason.
`../../../bin/fm-session-lock-lib.sh` counts the same process names as owning a session lock, and `../../../bin/backends/tmux.sh` classifies both its own launcher argv and `bin/fm-dsh-lib.sh`'s script paths as an agent.

## Routing

`bin/fm-dsh.py route` maps provider `deepseek` or a `deepseek/` model prefix to dsh, matched as omp resolves the selector (trimmed, case-insensitive); `claude*` maps to claude and everything else to omp, without changing non-DeepSeek dispatch.
The omp billing-route guard in `../../../bin/fm-api-key-guard-lib.sh` delegates its DeepSeek refusal to `bin/fm-dsh.py check omp`, so raw omp launches and fallback capability checks use the same rule.
`../../../bin/fm-spawn.sh` selects dsh for an implicit DeepSeek ship or scout; contradictory explicit DeepSeek adapters refuse rather than keep omp as a parallel route.
An omp launch omitting `--model` also checks its resolved shared Default role through this owner, so a catalog-listed DeepSeek default cannot bypass the cutover.
`bin/fm-dsh.py check` requires dsh for DeepSeek and requires a concrete model id (a DeepSeek route, followed by a non-empty id with no `/` or whitespace); `bin/fm-dsh.py canonical` gives that model its one identity, `deepseek/<id>`, which `../../../bin/fm-spawn.sh` records as the task model and `../../../bin/fm-control.sh` compares on relaunch, so `DeepSeek/<id>` and `deepseek/<id>` keep the same recorded effort, binding and conversation.
Relaunch checks that admission before stopping the running agent; dsh secondmates load the same native primary plugin as the main session rather than returning DeepSeek to omp.
`../../../bin/fm-dispatch-resolve.sh` rewrites only dsh profile models, provider-only or any DeepSeek spelling, to that canonical `deepseek/<id>`, and rejects contradictory adapter/model profiles without rewriting them.
Declared DeepSeek stand-ins are cross-harness dsh replacements, never native omp fallback-chain entries; the fallback schema and session-policy admission belong to [configuration](../../../docs/configuration.md#crew-dispatch-profiles-configcrew-dispatchjson).

## Launch posture

The launch swaps `HOME` for the task's private one, because `dsh-tui` keeps its model and effort preferences under `~/.dsh-tui` and has no flag for them.
Ships, scouts, primaries and secondmates link unrelated operator-home entries into the private HOME, retaining existing CLI authentication (including `gh` and `gh-axi` configuration) and tool state without copying those entries or credentials.
`.dsh` and `.dsh-tui` remain exclusively launch-local.
`FM_DSH_OPERATOR_HOME` selects that operator home when explicitly supplied, otherwise preparation uses the launching shell's HOME; the primary launcher and every DSH secondmate launch carry the value they were prepared from, so a secondmate spawned inside a DSH session links the operator's real entries, never that session's private HOME.
Exactly two paths are carried as environment variables resolved by the pane shell before `HOME` changes, so they name the operator's real files and nothing is copied: `GIT_CONFIG_GLOBAL` (the exported value, else `~/.gitconfig`) keeps the configured commit author and works beside the `GIT_CONFIG_*` `core.hooksPath` entry, and `NM_HOME` (the exported value, else `~/.no-mistakes`) lets `no-mistakes` reach the shared daemon, which it otherwise looks for under `$HOME/.no-mistakes`.
Run from a swapped `HOME`, `no-mistakes daemon status` reported the same running daemon as the operator's shell with `NM_HOME` carried and `daemon not running` without it; [runtime verification](../../../docs/verification/runtime-backends.md#deepseek-harness-dsh-tui) records the run.

Each launch stages a private `HOME` and `DSH_HOME` under the task's state directory, reproduces the installed profile's package tree inside it, copies the credentials, and writes the launch patch and model preferences there.
The installed profile's `node_modules` is reproduced file by file inside the launch root (hard links where the filesystem allows, copies otherwise) and never linked as a directory: Node resolves real paths before DSH's profile interception, so a directory link escapes the isolated profile and selects the launcher's own incompatible packages.
`bin/fm-dsh.py prepare` publishes `state/<id>.dsh-session`, which is the single binding consumed by busy classification and resume, and retires the generation that binding replaced.
`../../../bin/fm-teardown.sh` removes `state/<id>.dsh` and the binding, so the credentials copy and session logs do not outlive the task.
